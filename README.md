# llm-jp-decontam

学習データのレコードのうち、評価データと重なるものを取り除くためのツールです。名前の decontam は decontamination（学習データに混入した評価データの除去）の略です。入力は、チャット形式のレコード（`messages` の配列を持つ JSON オブジェクト）を 1 行に 1 件ずつ書いた JSON Lines を、gzip で圧縮したファイルです。

この文書では、次の呼び方と書き方を使います。

- `--data`：学習データのファイルを指定する引数。この引数に渡したファイルも `--data` と書きます。
- `--ref`：評価データのファイルを指定する引数。この引数に渡したファイルも `--ref` と書きます。
- 「行」：入力ファイル（JSON Lines）の 1 行。TSV の行は「TSV の行」と書きます。
- 「レコード」：不正な行（「入力ファイル」の節で定義）でない行
- 「ペア」：`--data` の 1 レコードと `--ref` の 1 レコードの組
- コマンドの書式の大文字の部分は、値に置き換えます。`{a,b}` は a と b のどちらかを選ぶこと、`[...]` は省略できることを表します。

処理は 2 つのコマンドで行います。

1. `decontam-stats` は、各ペアの重なりを数えます。両方のレコードを `--tokenizer` で選んだ単位（Unicode のコードポイントまたは SentencePiece のトークン）に分割し、次の 2 つを数えます。どちらかが 1 以上のペアを「重なりのあるペア」と呼び、TSV に書き出します。
   - 共通の n-gram の種類数。n-gram は連続する N トークンで、N は `--ngram-size` で指定します。種類数は、同じトークン列を 1 つと数えた数です。
   - 全体一致した文字列の種類数。全体一致は、`--ref` の N トークン未満の文字列のトークン列が、`--data` のいずれかの文字列のトークン列と完全に一致することです。

   どちらも、詳しい定義は「照合の方法」の節にあります。
2. `decontam-filter` は、その TSV を読み、利用者が指定した条件に合うペアについて、その `--data` 側のレコードを取り除きます。条件には、被覆率の下限と、全体一致があることを使えます。被覆率は次の 2 種類です。
   - `--ref` 側の被覆率：共通の n-gram の種類数 ÷ `--ref` のレコードの n-gram の種類数
   - `--data` 側の被覆率：共通の n-gram の種類数 ÷ `--data` のレコードの n-gram の種類数

## インストール

[uv](https://docs.astral.sh/uv/) と Python 3.13 以上が必要です。

```sh
git clone https://github.com/llm-jp/llm-jp-decontam.git
cd llm-jp-decontam
uv sync
uv run decontam-stats --help
```

最後の `--help` で引数の一覧が表示されれば、導入は完了です。

コマンドは、clone した `llm-jp-decontam` ディレクトリで `uv run` を付けて実行します。ほかのディレクトリからは、`uv run --project PROJECT_DIR decontam-stats ...` のように、PROJECT_DIR に `llm-jp-decontam` ディレクトリのパスを指定して実行できます。ファイルの相対パスは、コマンドを実行した場所を基準にします。

## 使い方の例

```sh
# --data と --ref を照合し、重なりのあるペアを TSV に書き出します。
# TSV には照合の設定が残らないため、TSV の名前に設定を入れておきます。
uv run decontam-stats --data train.jsonl.gz --ref eval.jsonl.gz \
  --output stats.char-n50-nfkc-lower-ws.tsv --ngram-size 50 --normalize nfkc-lower-ws --tokenizer char
# --ref 側の被覆率が 0.5 以上か、全体一致があるペアについて、--data 側のレコードを取り除きます。
uv run decontam-filter --data train.jsonl.gz --stats stats.char-n50-nfkc-lower-ws.tsv \
  --output train.filtered.jsonl.gz --min-ref-coverage 0.5 --short-texts
```

`--ngram-size 50` と `--min-ref-coverage 0.5` は書き方の例で、推奨値ではありません。

## 入力ファイル

`--data` と `--ref` は同じ形式です。UTF-8 の JSON Lines（1 行に 1 つの JSON）を gzip で圧縮したファイルです。行は LF だけで区切ります。行末の CR と、どの行でも先頭にある BOM（U+FEFF）は無視します。gzip かどうかは拡張子ではなく中身で確かめ、gzip でなければエラーで終了します。gzip のファイルを `cat` でつないだものも読めます。

学習データの例：

```json
{"id": "train-a1b2", "messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "...", "reasoning": "..."}]}
```

評価データの例（問題文だけで照合する場合）：

```json
{"id": "aime2024-q01", "messages": [{"role": "user", "content": "（問題文）"}]}
```

| キー | 必須か | 内容 |
|---|---|---|
| `id` | 任意 | TSV に書き出す識別子です。省略したときと `null` のときは空の文字列になります。文字列でない値は Python の `json.dumps(値, ensure_ascii=False)` の結果に変えます。そのため、数値の `12` と文字列の `"12"` のように、型の違う値が同じ文字列になることがあります。 |
| `messages` | 必須 | メッセージ（JSON オブジェクト）の配列です。空の配列のレコードは、どのレコードとも重なりません。 |
| `messages[].role` | 任意 | 発言者を表す文字列です。文字列でない値でも不正な行にはなりません。 |
| `messages[].content` | 必須 | 文字列です。 |
| `messages[].reasoning` | 任意 | 応答に至る思考の過程などの文字列です。文字列でない値でも不正な行にはならず、無視します。 |

照合に使うのは、すべてのメッセージの `content` と、`role` が `"assistant"` のメッセージの `reasoning` です。次のどれかに当てはまる `reasoning` は無視します。

- `role` がない
- `role` が文字列でない、または `"assistant"` 以外の文字列
- `reasoning` の値が文字列でない

表にないキー（`tool_calls` など）は、レコードの直下でもメッセージの中でも無視し、そこにある文字列は照合しません。

次の行は「不正な行」とし、照合しません。`decontam-filter` は、不正な行を常に `--output` に書き出します。

- JSON として解釈できない行（空行と、UTF-8 として読めない行を含む）
- JSON オブジェクトでない行
- `messages` がない行、または `messages` が配列でない行
- JSON オブジェクトでないメッセージ、または `content` がない・文字列でない（`null` や配列を含む）メッセージがある行

ファイルが改行で終わる場合、その改行の後に空の行があるとは数えません。末尾に改行のない最後の行も 1 行と数えます。たとえば、`{"messages": []}`、改行、改行、という内容のファイルは 2 行で、2 行目は空行なので不正な行です。

## `decontam-stats`

```sh
uv run decontam-stats --data DATA --ref REF --output OUTPUT \
  --ngram-size N --normalize {none,nfkc-lower-ws} --tokenizer {char,spm} [--tokenizer-model MODEL]
```

`--tokenizer-model` 以外の引数は必須で、既定値はありません。`--data` と `--ref` には、それぞれ 1 つのファイルを指定します。

### 照合の方法

照合には、「入力ファイル」の節で挙げた文字列を使います。以下では、これらを「照合対象の文字列」と呼びます。

1. 照合対象の文字列を `--normalize` で正規化し、`--tokenizer` でトークン列に分割します。
2. 1 つの照合対象の文字列の中で連続する N トークンを、n-gram とします。複数の文字列にまたがる n-gram は作りません。
3. 1 つのレコードのすべての照合対象の文字列から作った n-gram を、1 つの集合にまとめます。`role` は区別しません。各ペアについて、両方のレコードの集合に含まれる n-gram（以下「共通の n-gram」）の種類数を数えます。
4. `--ref` の照合対象の文字列のうち、1 トークン以上 N トークン未満のもの（以下「`--ref` の短い文字列」）は、n-gram を作れません。そこで、ペアの `--data` 側のレコードに、トークン列が完全に一致する照合対象の文字列があるかを調べます。ある場合、その `--ref` の短い文字列は「全体一致」したとします。
   - `--ref` の短い文字列が、`--data` の N トークン以上の文字列の一部として含まれるだけの場合は、全体一致としません。同様に、`--data` の N トークン未満の文字列が `--ref` の N トークン以上の文字列の一部であっても、全体一致とせず、共通の n-gram にもなりません。
   - `--normalize` で正規化した後の文字列（`none` のときは元の文字列）が空白文字だけのものは、`--ref` の短い文字列に含めません。この判定には、SentencePiece による正規化を行う前の文字列を使います。N トークン以上の文字列は、空白文字だけでも n-gram を作ります。

引数名と列名では、`--ref` の短い文字列を short texts と書きます。TSV の `matched_short_texts` は全体一致した `--ref` の短い文字列の種類数で、`decontam-filter` の `--short-texts` は全体一致が 1 つ以上あるペアを条件にする指定です。

### 引数

| 引数 | 内容 |
|---|---|
| `--data`、`--ref` | 入力ファイルです。 |
| `--output` | TSV の書き出し先です。拡張子にかかわらず、圧縮せずに UTF-8 で書きます。書き出しの動作は「出力ファイルの書き出し」の節を参照してください。 |
| `--ngram-size` | n-gram の長さ N（1 以上の整数）です。`--tokenizer char` ではコードポイント数、`--tokenizer spm` ではトークン数を表します。 |
| `--normalize` | `none` は、この引数による正規化をしません。`nfkc-lower-ws` は、Unicode NFKC 正規化、小文字への変換（Python の `str.lower`）、1 つ以上続く空白文字を半角スペース 1 つに置き換える処理を、この順に行います。空白文字は Python の `str.split` が区切りに使う文字で、改行とタブを含みます。先頭と末尾の空白文字の連続も、削らずに半角スペース 1 つにします。 |
| `--tokenizer` | `char` は Unicode のコードポイント 1 つを 1 トークンとします（コードポイント数は、見た目の文字数と違う場合があります）。`spm` は SentencePiece のモデルファイルでトークン列に分割し、トークン ID で比較します。 |
| `--tokenizer-model` | SentencePiece のモデルファイル（`.model`）です。`--tokenizer spm` のときは必須で、`char` のときは指定できません。学習するモデルが使うものと同じファイルを勧めます。学習のときと同じトークン列で重なりを数えられるためです（LLM-jp のモデルのファイルは [llm-jp/llm-jp-tokenizer](https://github.com/llm-jp/llm-jp-tokenizer) の `models/` にあります）。SentencePiece のモデルファイルに設定された正規化と、文字列の先頭に空白を足す設定（`add_dummy_prefix`）は、そのまま使います。これは `--normalize none` のときも同じです。 |

### 出力

TSV（タブ区切り）の 1 行目はヘッダー行です。2 行目以降に、重なりのあるペアを 1 ペアにつき 1 行で書きます。重なりのないペアは書きません。TSV の行は `data_line` の昇順に並び、`data_line` が同じものは `ref_line` の昇順に並びます。値は引用符で囲みません。

| 列 | 内容 |
|---|---|
| `data_line` | `--data` での行番号です。先頭の行を 0 とし、不正な行も数えます。 |
| `data_id` | `--data` のレコードの `id` です。 |
| `ref_line` | `--ref` での行番号です。数え方は `data_line` と同じです。 |
| `ref_id` | `--ref` のレコードの `id` です。 |
| `matched_ngrams` | 共通の n-gram の種類数です。 |
| `ref_ngrams` | `--ref` のレコードに含まれる n-gram の種類数です。 |
| `data_ngrams` | `--data` のレコードに含まれる n-gram の種類数です。 |
| `matched_short_texts` | この TSV の行の `--ref` のレコードにある `--ref` の短い文字列のうち、全体一致したものの種類数です。 |

種類数では、トークン列が同じものを 1 つと数えます。`id` に含まれるタブ、CR、LF は、半角スペースに置き換えて書きます。

```tsv
data_line	data_id	ref_line	ref_id	matched_ngrams	ref_ngrams	data_ngrams	matched_short_texts
12	train-c3d4	3	aime2024-q07	180	210	950	0
57	train-e5f6	8	choices-q11	0	0	431	1
```

行番号を 1 から数えるツール（`sed` など）で行を取り出すときは、行番号に 1 を足します。たとえば、`data_line` の値が 12 のとき、`--data` の該当する行は次のコマンドで取り出せます。

```sh
zcat train.jsonl.gz | sed -n 13p
```

標準エラー出力には、`--data` と `--ref` のそれぞれの行数と不正な行数、重なりのあるペアの数、重なりのあるペアに 1 回以上現れる `--data` のレコードの数を、人が読むための形式で表示します。

## `decontam-filter`

```sh
uv run decontam-filter --data DATA --stats STATS --output OUTPUT \
  [--min-ref-coverage X] [--min-data-coverage Y] [--short-texts]
```

`--data`、`--stats`、`--output` は必須です。`--min-ref-coverage`、`--min-data-coverage`、`--short-texts` は取り除く条件で、少なくとも 1 つを指定します。

### 引数

| 引数 | 内容 |
|---|---|
| `--data` | レコードを取り除く対象のファイルです。通常は `decontam-stats` に渡した `--data` と同じファイルです（別のファイルを渡す場合は、「制約と注意」の節を参照）。 |
| `--stats` | `decontam-stats` が書き出した TSV です。圧縮した TSV は読めません（エラーになります）。 |
| `--output` | 取り除かなかった行の書き出し先です（「出力」の節を参照）。 |
| `--min-ref-coverage X` | `--ref` 側の被覆率（`matched_ngrams` ÷ `ref_ngrams`）が X 以上のペアを、条件に合うものとします。`ref_ngrams` が 0 のペアは条件に合いません。 |
| `--min-data-coverage Y` | `--data` 側の被覆率（`matched_ngrams` ÷ `data_ngrams`）が Y 以上のペアを、条件に合うものとします。`data_ngrams` が 0 のペアは条件に合いません。 |
| `--short-texts` | `matched_short_texts` が 1 以上のペアを、条件に合うものとします。 |

X と Y には、0 より大きく 1 以下の値を指定します。

### 取り除くレコード

条件は TSV の行（1 行が 1 ペア）ごとに判定します。条件を複数指定したときは、どれか 1 つに合うペアを、条件に合うものとします。`--data` のあるレコードを含むペアのうち 1 つでも条件に合えば、そのレコードを取り除きます。

被覆率はペアごとに計算します。分母は、`--ref` 側の被覆率では `--ref` のレコード全体の n-gram の種類数、`--data` 側の被覆率では `--data` のレコード全体の n-gram の種類数です。そのため、複数の問題を `--ref` の 1 行にまとめると `ref_ngrams` が大きくなり、1 問とだけ重なるペアの `--ref` 側の被覆率が下がります。評価データは 1 問を 1 行に書くことを勧めます。

### 入力の検査

`--stats` のヘッダー行と各 TSV の行の列の数を検査します。さらに、取り除くレコードについてだけ、`--stats` の行番号と `id` が `--data` と対応しているかを、次の 3 点で検査します。どれかに当てはまると、`--output` を作らずにエラーで終了します。

- `data_line` が `--data` の行数以上
- `data_line` が不正な行を指している
- `--data` の `id` と TSV の `data_id` が違う（タブ、CR、LF を半角スペースに置き換えた後の値で比較）

この検査には、次の限界があります。

- 取り除かないレコードは検査しません。
- 変換（`json.dumps`、タブ・CR・LF の 1 文字ずつの置き換え）の後の `id` が空か、ほかのレコードと重複している場合は、`--stats` と `--data` の食い違いをエラーとして検出できないことがあります。
- `decontam-stats` に渡した `--ref` と照合の設定（`--ngram-size` など）は検査しません。

### 出力

`--output` には、取り除かなかった行を、不正な行も含めて元の順序で書きます。展開後の内容は、対応する入力の行とバイト単位で同一です（BOM も、末尾に改行のない行もそのままです）。拡張子にかかわらず gzip で圧縮するため、`.jsonl.gz` で終わる名前を勧めます。

標準エラー出力には、`--data` の行数、取り除いたレコードの数、書き出した行の数を表示します。不正な行の数は表示しません。取り除いたレコードの一覧は書き出しません。

## 出力ファイルの書き出し（両方のコマンドに共通）

- `--output` に指定したファイルが処理の開始時にすでにあると、エラーで終了します。上書きするオプションはないため、事前に削除してください。
- 書き出しの途中は、`--output` の名前の末尾に `.tmp` を付けたファイル（例：`stats.tsv.tmp`）に書き、最後まで成功したときに `--output` の名前に変えます。同じ名前の `.tmp` ファイルがすでにあると上書きするため、同じ `--output` を指定したプロセスを同時に 2 つ以上実行しないでください。
- エラーや Ctrl+C で終了したときは `.tmp` ファイルを削除し、`--output` は作りません。SIGKILL などで強制終了された場合は `.tmp` ファイルが残ることがあります。

## 終了コードとエラー

正常に終了したときの終了コードは 0 です。エラーで終了したときは、`--output` を作りません。エラーは次の 3 種類で、標準エラー出力への表示が違います。終了コードは、引数の書式の誤りが 2、それ以外が 1 です。

1. 引数の書式の誤り：使い方と誤りの内容を表示し、終了コード 2 で終了します。必須の引数がない、選択肢にない値を指定した、整数の引数（`--ngram-size`）に整数でない値を指定した、数値の引数（`--min-ref-coverage`、`--min-data-coverage`）に数値でない値を指定した、の各場合です。
2. このツールが検査する誤り：`ERROR:` で始まる 1 行を表示し、終了コード 1 で終了します。検査するのは次の場合です。
   - `decontam-stats`：`--ngram-size` が 0 以下。`--tokenizer spm` で `--tokenizer-model` がない。`--tokenizer char` で `--tokenizer-model` を指定した
   - `decontam-filter`：取り除く条件を 1 つも指定していない。`--min-ref-coverage` か `--min-data-coverage` の値が 0 より大きく 1 以下でない。「入力の検査」で誤りが見つかった
   - 両方：`--output` のファイルが処理の開始時にすでにある
3. それ以外の誤り：Python のトレースバックを表示し、終了コード 1 で終了します。たとえば、入力ファイルがない・開けない、`--data` か `--ref` が gzip でない、`--stats` が UTF-8 のテキストでない（圧縮した TSV など）、`--stats` の数値の列に整数でない値がある、`--output` の親ディレクトリがない、の各場合です。

## 制約と注意

- 不正な行の数は、`decontam-stats` の標準エラー出力で確認してください。`--ref` のすべての行が不正でもエラーにはならず、重なりのあるペアが 0 の TSV ができます。
- 照合対象の文字列を選ぶ機能はありません。
  - 多くのレコードに共通する同じ文字列（共通の system メッセージや、問題文の前に付く固定の指示文など。以下「定型文」）を両方のレコードが含むペアは、重なりのあるペアになります。N トークン以上の定型文は、照合対象の文字列の一部として含まれるだけでも共通の n-gram になります。N トークン未満の定型文は、`--ref` 側の照合対象の文字列全体と、`--data` 側の照合対象の文字列全体が、同じ定型文と一致する場合に全体一致になります。
  - このような定型文がある場合は、元の学習データと評価データから定型文を削除したコピーを自分で作り、gzip で圧縮して `decontam-stats` に渡してください。学習データのコピーは、元の学習データと行数、行の順序、各行の `id`、不正な行の位置を同じにしてください。定型文だけのメッセージは、配列から削除するか、`content` を空の文字列にしてください。`content` を `null` にすると不正な行になります。文字列の途中から定型文を削除すると、前後の部分がつながって新しい n-gram ができることがあります。その後、`decontam-filter` の `--data` には元の学習データを渡します。
  - `--ref` に `"assistant"` のメッセージ（評価データの解答など）を含めると、解答と重なる `--data` のレコードも重なりのあるペアになります。また `ref_ngrams` が増えるので、問題文とだけ重なるペアの `--ref` 側の被覆率は小さくなります。
- `--normalize none` では、文字列の中で空白文字が N トークン以上続く部分（コードのインデントなど）も n-gram になり、その部分だけで共通の n-gram になることがあります。`nfkc-lower-ws` では空白文字の連続を 1 つにまとめるため、この問題は起きにくくなります。
- `--tokenizer spm` では、同じ語句でも前後の文字によってトークン列が変わることがあります。そのため、同じ語句を含む 2 つの文字列でも、共通の n-gram にならない場合があります。
- N を大きくしても、共通の n-gram があるペアが増えることはありません。一方、`--ref` の短い文字列が増えるので、全体一致があるペアは増えることがあります。N を小さくすると、多くの文に現れる短い語句も共通の n-gram になり、TSV の行数が増えることがあります。
- 被覆率はペアごとに計算し、複数のペアにわたって合計しません。そのため、複数の評価問題と少しずつ重なる `--data` のレコードは、取り除かれないことがあります。
- `--output` の親ディレクトリがないことは、書き出しを始める時点（`decontam-stats` では照合をすべて終えた後）で初めて分かります。実行の前に作っておいてください。
- 複数の評価データを使うときは、`cat` で 1 つのファイルにつないでください。`ref_line` は、つないだファイルでの行番号になります。どの評価データかを `id` で区別できるよう、`id` には評価データの名前を入れておいてください。つなぐ前に、各ファイルの末尾が改行で終わっていることを確かめてください（`zcat FILE | tail -c 1 | od -c` で `\n` と表示されれば改行で終わっています）。改行で終わっていないと、前のファイルの最後の行と次のファイルの最初の行が 1 行になります。
- `--ref` の n-gram はすべてメモリに保持します。
- TSV には、照合の設定（`--ngram-size`、`--normalize`、`--tokenizer`、`--tokenizer-model`）も、照合したファイルも残りません。これらは TSV の名前などで記録してください。

## 開発

`uv sync` は、開発用のパッケージ（pytest、ruff）も入れます。

```sh
uv run pytest
uv run ruff check src tests && uv run ruff format --check src tests
```
